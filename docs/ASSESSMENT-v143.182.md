# Accounting assessment and debugging — v143.182

Date: 25 October 2026. Baseline: deployed v143.181 (`66c72ec`).

The review covered the current Accounting application through source inspection, isolated browser workflows, PostgreSQL fixtures, live read-only database checks, and release integrity checks. It is an assessment of the tested behavior, not a guarantee that every possible defect has been eliminated.

## Confirmed defects repaired

| Area | Reproduced problem | Result |
|---|---|---|
| Chart of Accounts | At 768px the description column shrank to about 49px; at 641px it could collapse completely. Toolbar controls clipped. | Usable columns, internal table scrolling, wrapping controls, and top-aligned rows. Phone layout preserved. |
| Account actions | The detached action menu could continue intercepting arrow keys after focus moved elsewhere. | Menu closes on focus departure/Tab and retains Enter, Escape, and arrow-key operation. |
| Account saves | Repeated saves could overlap; failures escaped the handler; an older response could close a newer editor. | Single in-flight save, stale-editor checks, error recovery, and accurate saved-versus-refresh-failed feedback. |
| Business settings | Background refresh replaced unsaved fields and marked the replacement as the saved baseline. | Edited fields survive; untouched fields refresh; dirty status and Undo use the actual server baseline. |
| Offline saves | Equal timestamps or a backwards device clock could make dependent saves block each other. | Dependencies follow persisted queue order; failed predecessors still block dependent changes. |
| Journal dates | Receipt dates could replace the main posting date when an entry was loaded, edited, or collected for submission. | The saved main date travels separately as `postingDate`; same-month receipt dates remain intact. |
| Journal sync | A caller could return before an already-running synchronization completed. | Concurrent callers await the current sync promise. |
| AI Journal | A temporary receipt/ID-preview failure could leave unchanged draft rows stuck in an error state. | Transient checks remain pending and retry; invalid source data does not enter a retry loop. |
| AI HR | Paid leave allowance checks omitted leave already taken through finalized attendance. | Finalized attendance is included without double-counting linked leave; unpaid handling follows normal HR approval. |
| Financial reports | A selected range spanning years could silently omit the earlier year. | Activity is included in labeled annual sections; annual opening balances are not added twice. Balance Sheet remains a point-in-time report. |
| Reconciliation | Required explanations were hidden inside collapsed supporting documents; multi-year cash activity could be incomplete. | Explanations appear beside the comparison. Multi-year cash reconciliation includes the posting periods without duplicating annual openings. |

Assertions continue to test the current behavior rather than restoring retired UI.
- Static inventory covered 1,820 repository files, 604 canonical source modules, and 369 generated outputs; no duplicate source inclusions or unmapped source modules were found.
- Canonical sources were rebuilt; structural ownership, generated bytes, local asset references, release hashes, and Git whitespace checks were verified.

## Database change

Migration `20261025114147_journal_posting_date143182.sql` adds the journal header date to the read-only `journal_window14333` response and changes its cache revision prefix. The function remains STABLE and SECURITY INVOKER with the same search path and execution grants. Its filters, ordering, valuations, opening calculations, and amounts are unchanged.

The migration was tested against an isolated PostgreSQL fixture before application. Live verification loaded 122 lines and confirmed their main dates match the saved journal headers. No financial transactions, balances, account codes, or historical records were rewritten. Old offline caches gain the new date field on their next successful Sync. Existing immutable queued edits are not rewritten; any already-conflicted work remains available for review.

## Boundaries and remaining advisories

- Live Google authorization, email delivery, and real posting/approval flows were not exercised with production transactions. Their application paths were tested with fixtures where available.
- Supabase reported the project as `ACTIVE_HEALTHY`. The security advisor returned no ERROR-level findings, but existing WARN-level hardening notices remain: three mutable function search paths, `pg_net` in public, an upgrade-incompatible `regprocedure` column, and disabled leaked-password protection. Public/pre-request and authenticated SECURITY DEFINER advisories need function-specific interpretation; broad permission revocation would break intended application APIs.
- Performance notices remain for 105 unindexed foreign keys, 33 RLS initialization-plan findings, 19 multiple-permissive-policy findings, and five unused indexes. These are advisor findings, not evidence that all listed objects require changes. No speculative index or policy changes were applied during this bug-fix release.
- The legacy fresh installer passes its documented acceptance contract but does not bundle every later optional feature migration. The new posting-date migration is retained separately for existing installations; this release does not claim a full portability rebuild.
