# Google history and database Excel safeguard — v143.194

The business-owned Accounting Web workbook receives saved database changes through a durable queue. A database event wakes the worker; a successful Sheets readback clears that event. This does not poll and rewrite the workbook every minute. Errors remain visible in Settings, with a manual retry.

Current Year Journal contains the current Vientiane calendar year. Open Years Journal retains other unclosed years. Whole-year closure captures a database snapshot, creates fixed Records/Journal/report History tabs and verifies their contents before sealing them. Routine synchronization never overwrites sealed history. The Google owner can still edit a protected history tab; such edits block later cleanup.

Settings → System & Tools → Backup & Export contains Google Sheets — Current Year & History. Cleanup requires administrator authentication, a fresh record/field and report-cell comparison, a separate readable Excel workbook generated directly from a fresh database snapshot, acknowledgement that the file was saved, and the exact final confirmation phrase. The server repeats the comparison and the deletion transaction rechecks the selected records under locks. Differences create a Cleanup Comparison report. A missing/changed history, download initiation error, cancelled review, changed account, stale selection or missing Excel token blocks deletion. The backup starts an actual browser download and the final dialog provides a Download again link. The browser cannot prove that a native download was saved; the administrator must confirm that explicitly.

Closed-year cleanup preserves year/month locks and master data. Scoped operational reset keeps its prior selection/permission/backup checks and now passes the archive gate. Legacy bulk-clear RPCs cannot bypass this gate. This workflow does not change normal single-entry corrections and authorized void/audit operations.

Saved financial reports use posted records and integer-cent aggregation. Profit and Loss excludes legacy year-end closing journals; the Balance Sheet includes earnings not already transferred into equity. Journal preserves all statuses, and General Ledger includes posted entries. History tab creation, initial values and protection are atomic. Bulk resets retain deletion revisions even when the underlying reset uses TRUNCATE; only events captured before the snapshot are acknowledged.

Validation: record/field comparison, lossless large Unicode data, stable compound record IDs; PGlite database snapshot, stale selection, year locks, single-use/expired permits, event-arrival races, non-admin denial and Excel prerequisite; actual Edge worker atomic-write retries, corrupted history/report cells, immutable history and fresh-snapshot tests; Chromium cancel/failure/account-change/final-confirmation flows and actual XLSX parsing; existing archive FX, archive engine, archive UI, reset database/cache and cross-year report tests. The old test-ledger-reset143108 harness is obsolete: it references removed pagination and omits current memo/rate helpers; v143.154 intentionally removed report pagination, and the published report source is unchanged in this release. Production verification read back the live workbook and confirmed the financial record counts were unchanged. No production cleanup was executed. No year is fully closed yet, so live year-history tabs cannot be exercised on real closed data; the closed-year destructive path was tested only in an isolated database.

Workbook data/report mirrors do not enable posting by editing cells. Raw Data and Source Records preserve business records; attachments remain stored at their original locations. Authentication credentials, OAuth tokens and recovery secrets are excluded.
