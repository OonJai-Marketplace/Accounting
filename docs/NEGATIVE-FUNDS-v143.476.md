# Negative user-fund bell notifications

A confirmed staff save or journal post already changes `workspace_fund_revision379` once per affected owner per database transaction. A deferred trigger checks the complete result once and stores only negative assigned-fund balances. It reuses the existing working-standing calculation, including saved draft/returned/submitted entries, custody checkpoints and posted-line deduplication. Unsaved typing and device-only queued work do not send alerts; their successful server save does.

One compact record per owner holds separate fund/currency shortfalls. Unchanged deficits cause no update or event. Funding recovery writes one empty-deficit event, removing the notice. A later shortage reuses that record with a higher revision. Failed/rolled-back transactions publish no events. Alert calculation failures are logged as database warnings and cannot reject the underlying save.

Administrators receive saved changes through one passive Realtime subscription while the app is visible. The event supplies the complete compact notice; it does not fetch balances, reload journals, run a timer, schedule a job, or create a retry loop. A single catch-up read of saved notices runs when the subscription connects; explicit Home refresh/Sync Now can also refresh those notices. Hiding, disconnecting, signing out or losing access releases the listener. The bell displays one persistent Budget needed notice per user and opens their remaining-funds screen. Positive balances in another fund or currency do not hide a shortfall.

Existing notifications start from the next successful transaction; installation performs no historical balance scan and changes no journal or financial record. Independent phone saves use the same server trigger; the administrator bell remains in the existing desktop/tablet accounting workspace.

Validation: synthetic PostgreSQL fixtures tested complete 20-line saves with exactly one deferred check, saved-to-posted deduplication, unchanged shortages, exact-zero recovery, renewed deficits, rollback and admin-only permissions. Client tests cover duplicate/stale events, separate currencies, opening the user, connection replacement, session isolation and absence of polling/retry loops. Existing working-standing tests, generated-source checks, cache-key checks and repository structure checks pass. Production schema/privileges/publication were verified read-only. No live financial records were created for testing; physical-device timing was not measured.
