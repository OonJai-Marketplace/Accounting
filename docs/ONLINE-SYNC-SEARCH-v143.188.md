# Online save, complete refresh and Settings search — v143.188

Search now indexes the current Settings headings and controls, including Website Update, instead of an eight-item legacy list. Local navigation and loaded records render immediately. Selecting a Settings result reveals its actual subsection. Permissions and account/query changes remain checked; document search cannot delay navigation results.

Online account saves attempt the database even after an earlier cached read encountered a slow connection. A slow browsing fallback no longer declares the entire connection offline. After a confirmed account or sub-account write, reference data is read directly from the database with a bounded request and no cache fallback. The confirmed reference copy also becomes available offline. Parent grouping accounts therefore appear in the sub-account selector after a successful save. Failed writes retain the editor; refresh errors distinguish an already saved account from an unsuccessful write.

Online journal posting immediately attempts synchronization and reports the validated database receipt. Durable device storage remains a recovery journal for crashes, offline work and uncertain responses; it is never presented as database confirmation. Immutable references, original content checks, ordered changes/audit deletions and permission checks remain in force. Database-confirmed entries awaiting history reconciliation no longer count as unsent uploads.

Desktop login/reload now waits for its online sync attempt before dismissing preparation. Pending work uploads first; six ordered stages refresh accounts/settings, approvals/schedules, audit/submissions, journal/ledger, HR/payroll, and documents/AI inboxes. Manual refresh checks all eligible areas anew. Errors remain visible by area and in Sync details, including an expired Google connection. Other completed database refreshes are retained. Offline reopening uses downloaded data and retains pending work. Regular background refresh still honors the existing two-minute idle rule.

Validation uses isolated browser/database fixtures; it does not create or modify production accounting records. Covered cases include slow reads, stale connection recovery, parent creation and immediate selection, updated offline reference copies, online journal receipts, offline retention/reload upload, retry deduplication, six-stage login completion, search routing, partial Google failure, and desktop/phone cache consistency. Existing durable-journal tests cover conflicts, uncertain replies, edits/voids, recovery and actor isolation.
