# Template recovery, payroll reports and sign-in — v143.275

## Implemented
- Review 1/2/3 named signatories and editable roles before opening each generated report. Save defaults per report type using the existing owner preference record; retain voucher defaults. Cancel and failed saves keep the report unopened. Existing salary voucher receiver/approval rules remain separate.
- Remove Received by from payroll calculation reports, including old saved editable copies. Names are focusable on signature lines, survive save/reopen and are retained at print instead of prompting twice. Insert → Signatories edits the report choices/defaults.
- Decouple page numbers from footer placement: page 1 and subsequent pages are numbered even with a last-page-only or disabled image footer. Below-content images have two lines of space by default, with a three-line option; page numbers remain at the bottom. Preserve independent numbers in Word export too.
- Fix the reported sign-in exception: remembering a workspace before any tab is active built an invalid `# .r79[aria-busy="true"]` selector. Resolve the actual element by ID, tolerate absent views and keep busy reports uncached. Authentication credentials and permissions are unchanged.
- Account-owned template collections now sync with version checks and owner RLS. Local encrypted copies remain usable offline. Startup, explicit checks and reconnects reconcile saved copies; writing to the device is distinguished from cloud confirmation. A lost response is reconciled from the saved cloud revision. No sidebar sync panel is added.
- Merge disjoint template edits. Conflicting edits/deletions require explicit review; number collisions never silently renumber templates. Users may retain the device backup, adopt the cloud list, then import selected items as new identities. Permanent numbers and deletion tombstones are also enforced by the database.
- Recover previous local versions and up to eight retained collection snapshots, export/import selected templates and restore a verified cloud copy after damaged local storage. Retain the damaged bytes before replacement. These controls do not prove that a user's specific old templates still exist; their original browser must supply its saved list or backup.
- Foreign payroll reimbursements now use explicitly selected supported expense mappings, paired actual LAK expense and mapping-offset rows, and saved rates. Different employees may use different expense categories. Keep original payroll values and explicit conversion rounding; unsupported/missing mappings, edited business amounts and incomplete pairs block preparation. No new tax bridge is invented.
